# 2026-10-13

## Que aprendi

Ayer y hoy pase mis trabajos de la U de mi GitHub universitario a mi GitHub personal, y en el camino aprendi varias cosas de git que no sabia.

Para cambiar el autor y el correo de los commits viejos se usa `git filter-branch` con `--env-filter`, y para sacar una carpeta de todo el historial (no solo del ultimo commit) se usa con `--index-filter`, osea si uno sube algo que no debia, borrarlo en un commit nuevo no sirve pq sigue en los commits de antes, toca reescribir el historial y subirlo con `git push --force-with-lease`. Antes de hacer esto es mejor sacar un respaldo con `git bundle`.

Tambien aprendi que GitHub guarda aparte la lista de Contributors que sale en la pagina del repo, y aunque uno reescriba el historial esa lista no se actualiza, en mi caso la unica forma de arreglarla fue borrar el repo, crearlo otra vez vacio y volver a subir todo.

Con GitHub Pages hay dos formas de publicar, con GitHub Actions, que sirve para proyectos que hay que compilar como los de React con Vite, o desde una rama, que sirve para paginas de HTML, CSS y JS que no se compilan. Si se publica desde una rama hay que poner un archivo `.nojekyll` vacio, porque si no GitHub ignora los archivos que empiezan con `_`.

Y en React, el linter me marco un aviso por llamar `setState` directo dentro de un `useEffect`, lo arregle guardando la respuesta del fetch junto con la url a la que pertenece y calculando `datos`, `cargando` y `error` en el render.

## Como lo use

```
git filter-branch --env-filter 'export GIT_AUTHOR_EMAIL="mi@correo.com" GIT_COMMITTER_EMAIL="mi@correo.com"' -- main
git filter-branch --index-filter 'git rm -r --cached --ignore-unmatch -q carpeta' -- main
git push --force-with-lease origin main
```

En Vite, para que funcione en GitHub Pages dentro de una subcarpeta:

```js
export default defineConfig({
  plugins: [react()],
  base: './',
})
```

## Lo que me costo

Entender que lo que se ve en la pagina de GitHub no siempre es lo mismo que hay en los commits, la API decia una cosa y la pagina otra. Y que cuando un workflow queda en `startup_failure` el boton de Re-run no hace nada, toca lanzar uno nuevo.
